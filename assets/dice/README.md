# assets/dice — the die

```
raw/face-src.png   one blank die face, generated by Scenario (flux + the board LoRA)
raw/atlas.png      the baked 3x2 face atlas — a build artifact, kept so it can be eyeballed
models/die.glb     the asset the game loads
```

Rebuild both derived files from the source face:

```bash
python3 tools/make-dice.py --check
```

## Why this one is built rather than reconstructed

Every other 3D asset here comes back from Scenario's image-to-3D step. A die cannot, and it is
worth being precise about why, because the failure is quiet.

Image-to-3D sees one render, so it sees at most three faces. The other three are invented, and
invented pip counts are wrong about as often as they are right. Worse, a die's faces are not
independent: **opposite faces must sum to 7**, and the three faces meeting at a corner must run
counter-clockwise for a right-handed die. Nothing in a reconstruction pipeline knows either rule,
and a die that breaks them still looks like a die in a screenshot — you only notice when a player
reads 3 on top and 5 underneath.

So the work is split along the line of what is *countable*:

| | comes from |
|---|---|
| The surface — colour, grain, worn edges, the board's look | **Scenario**, same flux + LoRA pair the tiles use |
| The pip layouts, which value sits on which face, the geometry | **`tools/make-dice.py`** |

That keeps the die matching the rest of the board while making the numbering a property of the
build rather than a hope about the generator.

## The contract

Unit cube, **centred on the origin** — extents −0.5 … +0.5 on every axis. This is deliberately
unlike the tiles, which sit on the ground plane with their origin at the base: a die is going to
be tumbled, and a mesh that rotates about its own centre is the one that behaves.

Scale it to whatever the board wants and place the centre half a die-height above the surface.

Faces, in engine axes (+X right, +Y up, +Z toward the viewer):

| Face | Value | | Face | Value |
|---|---|---|---|---|
| +Y (top) | **1** | | −Y (bottom) | **6** |
| +Z (front) | **2** | | −Z (back) | **5** |
| +X (right) | **3** | | −X (left) | **4** |

Read it as: 1 up, 2 facing you, 3 on the right — the standard right-handed die. Every opposite
pair sums to 7. **Code that rotates the die to show a rolled value depends on this table**, so
it is asserted at build time rather than left as a comment.

- 486 verts, 768 triangles, one material, one baked texture
- Corners rounded by 0.10 of the cube. The roundover eats only the outer border of each face,
  which is bare material by construction, so no pip is ever bent around an edge
- Texture sampler is CLAMP_TO_EDGE on both axes — the atlas packs six faces, and a wrapping
  sampler would bleed one face's border into the next

## What `--check` actually checks

Not the layout table — the table is what could be wrong. It checks the artefacts:

1. **The convention**, before anything is drawn: opposite faces sum to 7, and 1-up/2-front puts
   3 on the right.
2. **The atlas**, by flood-filling dark blobs in each cell and comparing the count to what that
   cell is supposed to hold. This is what caught the first build: the crop of the source face
   reached into the drop shadow at its bottom-right corner, and every face came back with a
   seventh "pip".
3. **The shipped GLB**, read back from its own bytes — it walks the POSITION/TEXCOORD accessors,
   finds the vertex at the centre of each face, follows its UV into the atlas cell that face
   really samples, and counts the pips there. It checks winding at the same time, since a face
   wound inside-out is invisible from the front and would otherwise ship unnoticed.

## Regenerating the surface

The source face is one Scenario image: a blank die face, no pips, flat and square. Prompt notes:

- Ask for **no dots, no pips, no numbers** explicitly — the model adds them otherwise, and a
  pip baked into the source lands on all six faces.
- `lorasScale: 0.6` rather than the tiles' 0.8. At full strength the LoRA reads "board tile" and
  returns a slab in a diorama; 0.6 keeps the palette and the chalky matte finish without the
  staging.
- What comes back is a modelled block, not a flat swatch — bevelled border, rounded inner
  corner, drop shadow down the right and bottom. `--crop` takes the flat interior only. The
  default `0.25,0.25,0.75,0.75` is the widest crop with nothing below the pip threshold anywhere
  inside it, and at the default 512 cell it also happens to be 1:1. Re-check it against a new
  source rather than assuming it carries over.
